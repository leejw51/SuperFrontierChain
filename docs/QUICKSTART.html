SFC quickstart

Super Frontier Chain (SFC) is an MIT-licensed Rust blockchain framework with Ethereum contract execution, 100 ms blocks, and Cap’n Proto RPC over HTTP/3 synchronization. The runnable topology is one development sequencer and verifying followers. Distributed validator consensus is not integrated.

New homes use protocol v3 with Merkle Patricia state commitments. Use a fresh home for older flat-hash chains; existing chain directories are preserved. See binary formats and configuration editing.

Requirements

  • Rust and Cargo, a C/C++ toolchain, and libclang for RocksDB.
  • The capnp compiler for generated protocol bindings.
  • Make, uv, Python 3.13 and pycapnp for lifecycle commands and local test networks (make codec-setup).
  • Apple Silicon + Metal for GPU/HYBRID verification; the default Rust/MLX runtime needs no Python. GPU is the default; use SFC_VERIFICATION_BACKEND=cpu on other platforms.
  • Node.js and npm for integration tooling and dashboard builds.
  • macOS or Linux for the Python service's file locks and Unix control socket.

Run commands from the repository root. make doctor checks the main native tools; it does not install dependencies. Builds use Cargo.lock.

Start a node

make help
make doctor
make codec-setup  # Python tooling for the optional service/testnet commands
make start

make alone shows help. make start builds the optimized release binary, initializes ~/.superfrontierchain/node/ if configuration is absent, and starts a background node. Existing configuration and state are reused. For CPU mode use SFC_VERIFICATION_BACKEND=cpu make start; for HYBRID use SFC_VERIFICATION_BACKEND=hybrid make start. An already-running service must be stopped before changing its mode. See backend settings and measurements.

Open the dashboard. It refreshes every two seconds and shows height, committed TPS, block timing, pending transactions, recent blocks, accounts, retention, and configured sync transport. TPS is a recent block-window average; an empty chain has no meaningful rate yet. Connection status refers to the dashboard API, not peer connectivity.

curl -s http://127.0.0.1:8545/ \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'

curl -s http://127.0.0.1:8545/dashboard/stats -o /tmp/sfc-stats.capnp
python3 scripts/sfc_codec.py /tmp/sfc-stats.capnp
make peer-status

Expected chain ID: 0x1e61 (7777). Peer status uses TCP by default; select HTTP/3 with TRANSPORT=http3.

Stop and restart

make stop
make start

Stop requests graceful shutdown and allows ten seconds before forced termination. Repeated commands are safe. The repository-wide stop command also stops its foreground nodes, testnet and stress processes. It leaves unrelated processes running.

To start in a custom home (stop still applies repository-wide):

make start DATA_DIR=.sfc-local
make stop DATA_DIR=.sfc-local

Custom homes still default to the same ports. Change their config.jsonl listener addresses before running multiple independent services. If CONFIG overrides the default path, that file must already exist.

For foreground operation on a new home:

make init DATA_DIR=.sfc-foreground
make run DATA_DIR=.sfc-foreground
# Ctrl-C stops the foreground node.

make dev uses a debug build; make run-log runs in the foreground and appends node diagnostics to DATA_DIR/node.log.

Pruning and archive mode

The generated configuration enables pruning:

{"retention":{"mode":"pruned","seconds":60}}

The cutoff follows committed block time. Old blocks and receipt indexes expire; current balances, code, and contract storage remain. Pruned history segments span min(retention_seconds, 60) seconds; the boundary segment may temporarily retain less than one extra segment. Archive segments span one hour. Disk space is reclaimed through RocksDB compaction rather than immediately upon logical deletion.

To create an archive home:

make archive DATA_DIR=.sfc-archive
make start DATA_DIR=.sfc-archive
make stop DATA_DIR=.sfc-archive

Archive mode keeps all future history. It cannot restore already pruned blocks.

Multiple nodes

Stop a default single node first to free its ports, then run:

make stop
make testnet

The Python supervisor starts one sequencer and three followers. Default RPC ports are 8545–8548; HTTP/3 UDP ports are 26656–26659. Each node has its own data and node.log under ~/.superfrontierchain/testnet/node-N/. Submit transactions to node 0. Followers replay its blocks over certificate-pinned HTTP/3. Ctrl-C shuts down the whole group. The supervisor restarts crashed processes with a bounded retry budget.

make testnet NODES=6 TESTNET_DIR=.sfc-six RPC_PORT=8645 PEER_PORT=27656

Use a new home when changing node count. Existing network configuration is reused, so port options only apply when creating the network.

Troubleshooting

  • Startup failed: inspect node.log and service.log; check port conflicts.
  • Genesis mismatch: use the original genesis for existing data or a fresh home.
  • Follower missing history: configure an archive peer with the same chain and genesis. Automatic snapshot sync and peer failover are not implemented.
  • TLS error: pin the upstream's certificate and use its matching server name; generated identities use localhost.
  • Dashboard stale: check whether the node is running and inspect its logs.
  • Corrupt journal: startup deliberately refuses corrupted WAL records; there is no automatic destructive repair or silent rollback.
